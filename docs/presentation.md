## 第一页：项目经理数字人

### 传统项目管理的困境

**信息孤岛**
- 需求在文档里，任务在看板上，进度在各种群里
- 项目经理每天花大量时间"找信息"、"对齐信息"

**被动响应**
- 问题发生了才知道，风险暴露了才处理
- 救火式管理，疲于奔命

**重复劳动**
- 每天问进度、写日报、催任务
- 每周整理周报、复盘会议
- 大量时间消耗在"信息搬运"上

---

### 我的创意：AI 项目经理数字人

**让 AI 承担项目经理的日常职责，释放人的精力去做更有价值的事。**

我们打造的不是一个项目管理工具，而是一个**具备全链路项目管理能力的 AI 数字人**——

**「小派」**

---

### 小派的全链路能力

**需求阶段 → 智能规划**
- 理解需求文档，自动拆解用户故事
- 智能估算工作量，生成迭代计划
- 合理分配资源，平衡团队负载

**执行阶段 → 实时洞察**
- 持续监控项目状态，掌握全局动态
- 识别进度偏差，预判潜在风险
- 主动推送关键信息，让问题无处隐藏

**协作阶段 → 主动沟通**
- 每日自动生成状态播报
- 实时风险告警，第一时间触达
- 智能周报生成，告别重复劳动

**决策阶段 → 智能建议**
- 基于数据分析，给出行动建议
- 推荐最优方案，辅助科学决策

---

### 核心理念

> **从"人驱动工具"到"AI 驱动管理"**
>
> 小派不是等你来问的助手，而是主动帮你盯着项目的数字人。
>
> 它有自己的"工作日程"，会观察、会思考、会行动。

## 第二页：OpenClaw 集成方案

### 如何让小派"动起来"

通过 OpenClaw 的能力，赋予小派自动化执行的能力：

**定义 Skills（技能）**
- `projex-status`：获取项目状态——迭代进度、发布状态、风险分析
- `dingtalk-notify`：发送钉钉消息——将信息推送到团队群

**编排 Lobster 工作流**

```
每日状态推送
├─ 触发：每天早上 9:00
└─ 流程：获取状态 → 分析风险 → 生成日报 → 推送钉钉

实时风险告警
├─ 触发：检测到风险变化
└─ 流程：分析详情 → 生成告警 → 立即推送

智能周报生成
├─ 触发：每周五下午 5:00
└─ 流程：汇总数据 → AI 生成周报 → 推送到群
```

**设计思路：** 给 AI 安排"工作日程"，让它像真正的项目经理一样，按时完成自己的职责。

**已实现的核心功能**

- 任务看板（拖拽、多视图）
- 团队成员管理、权限控制
- 数据统计与可视化

---

### AI 能力层（基于 OpenClaw）

**Skills 技能定义**

```
projex-status
├─ get_sprint_status    # 获取迭代状态
├─ get_release_status   # 获取发布状态
├─ get_risk_analysis    # 风险分析
├─ generate_daily_report   # 生成日报
└─ generate_weekly_report  # 生成周报

dingtalk-notify
├─ send_message         # 发送消息
├─ send_daily_status    # 每日状态推送
└─ send_risk_alert      # 风险告警
```

**Lobster 工作流编排**

```
每日状态推送  →  cron: 0 9 * * *（每天9点）
实时风险告警  →  trigger: risk_change（风险变化时）
智能周报生成  →  cron: 0 17 * * 5（每周五5点）
```
